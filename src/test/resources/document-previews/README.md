# Document preview fixtures

Synthetic files for the preview renderer tests. None is case data. Each image is a solid colour with a black
square in its **stored** top-left quarter, so a rendered page shows which frame it came from (the colour) and
which way up it was drawn (where the square landed).

They are written by `DocumentPreviewFixtures` in the test sources, and `DocumentPreviewFixturesTest` checks on
every build that the committed files still have the structure below. To regenerate them, from the repository root:

```bash
REGENERATE_DOCUMENT_PREVIEWS=true ./gradlew test --tests '*DocumentPreviewFixturesTest'
```

Regenerated bytes can differ between JDK/PDFBox versions; the structure must not.

| File | Pages / frames | Stored size, colour | Notes |
|---|---|---|---|
| `three-pages.pdf` | 3 | A4 portrait, landscape, portrait | Helvetica text "page N" |
| `photo.jpeg` | 1 | 640×480 blue | JFIF only, no EXIF |
| `photo-exif-6.jpeg` | 1 | 640×480 green | EXIF APP1 after JFIF APP0, orientation 6: previewed portrait, square top right |
| `scan.png` | 1 | 480×640 red | |
| `text-chunks.png` | 1 | 480×640 red | `scan.png`'s image with a `zTXt` and a compressed `iTXt` chunk after the IHDR, each about 8 KB of deflated zeros inflating to 8 MiB; the preview must never inflate them |
| `two-frames.tiff` | 2 | 400×600 red (LZW), 600×400 blue (Deflate) | portrait then landscape |
| `three-frames.tiff` | 3 | 400×600 bilevel white (CCITT T.6), 300×200 green (PackBits), 300×200 yellow (none) | third frame orientation 6: previewed portrait, square top right |
| `oversized-tile.tiff` | 1 | 16×16 grey, one declared 8192×8192 tile (Deflate) | 162 bytes, written field by field; the tile is about 67 million pixels and its only packet is not a deflate stream, so it must be refused from the directory before any decode |
| `aliased-payloads.tiff` | 1 | 1×1 grey, one uncompressed strip | the third review's aliasing probe: 56 JPEGTables entries (UNDEFINED), 64 in the directory, all naming one 64 KiB payload of zeros; written field by field (`DocumentPreviewFixtures.aliasedPayloads`, so the same on every JDK). The JDK alone reads the payload once per entry, about 3.6 MB from a 66 KB file; `TiffStructure` must refuse it before ImageIO sees it |
| `three-pages.docx` | 3 pages | Word, "Synthetic Word fixture, page N" | hard page break after pages 1 and 2 (POI `XWPFDocument`) |
| `table-and-image.docx` | 2 pages | Word, 4×3 table, then the `scan.png` picture | page break before the picture |

The other compression modes (None, LZW, Deflate, ZLib, PackBits, CCITT RLE/T.4/T.6; JPEG, Compression 6 and 7, only
to prove it is refused before ImageIO), all eight
orientations, damaged, oversized and mismatched inputs, and the hand-written tiled and stripped TIFFs
(`DocumentPreviewFixtures.tiledGrey`/`strippedGrey`), and the malformed directory structures (overlapping,
out-of-file, overflowing, looping, over-long and mistyped entries, EXIF pointers, strips aliasing one payload, built with
`DocumentPreviewFixtures.entry`/`withLeadingEntries`), are generated inside `PreviewRendererTest` and
`TiffStructureTest` from the same class. `DocxRendererTest` derives macro-enabled and encrypted copies of the DOCX fixtures with
`DocumentPreviewFixtures.withMacros`/`encrypted`; the converter's PDFs come from `DocumentPreviewFixtures.pdf(n)`, so
they prove page counts read back, not Word layout.
